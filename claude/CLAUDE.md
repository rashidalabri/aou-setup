# All of Us Researcher Workbench (Verily Workbench)

This machine is a JupyterLab app in an *All of Us* (AoU) Researcher Workbench 2.0 workspace on
Verily Workbench (GCP). It has Controlled Tier (CT) access to participant data. Treat everything
under the CDR, the genomic buckets, and derived outputs as sensitive.

## Data rules (non-negotiable)

- **Participant data never leaves the workspace.** Do not paste row-level data, person_ids, or
  small-cell results into web searches, MCP/connector tools, artifacts, issues, commits, or any
  external service. Only read from the CDR and genomic buckets; write outputs to workspace buckets.
- **Small counts.** The AoU Data and Statistics Dissemination Policy forbids publishing counts of
  1–20 participants (or values that let someone derive them). Show them as `<20` or `≤20` in
  anything meant for sharing, and point it out when a result has small cells.
- Don't print raw participant rows to the terminal unless the user asks. Use aggregates, `.shape`,
  `.head()` on derived columns, or schema-only views.
- Never commit data files (CSV/TSV/parquet/VCF/plots containing data) to git.

## Cost rules

- Dry-run BigQuery first: `bq query --dry_run --use_legacy_sql=false '...'` reports bytes scanned.
  Ask before running anything over ~1 TB. Select only the columns you need. Never `SELECT *` on
  big tables (`measurement`, `observation`, `drug_exposure`, `condition_occurrence`, wearables).
- Genomic buckets are requester-pays: pass `--billing-project=$GOOGLE_PROJECT` to `gcloud storage`,
  `-u $GOOGLE_PROJECT` to `gsutil`, and `gcs_requester_pays_configuration=$GOOGLE_PROJECT` to Hail.
- Test on a small subset (one chromosome, a few samples) before you scale up. Ask before you launch
  batch jobs (dsub, Cromwell, Nextflow) or create cloud resources (`wb resource create ...`).

## Environment

`~/.bashrc` loads the platform variables (`~/load-env.sh`) and then `~/.aou/env.sh`
(generated by aou-claude-setup). Run `cat ~/.aou/env.sh` to see this workspace's values.

| Variable | Meaning |
| --- | --- |
| `GOOGLE_PROJECT` / `GOOGLE_CLOUD_PROJECT` | Workspace GCP project; billing project for queries and requester-pays reads |
| `WORKSPACE_CDR` | CDR BigQuery dataset, `project.C2025Q4R6` (CT v9) |
| `WORKSPACE_CDR_INDEX` | Cohort-builder index dataset (e.g. `T_ENT_person.has_whole_genome_variant`) |
| `WORKSPACE_BUCKET` / `WORKSPACE_TEMP_BUCKET` | Persistent / 14-day auto-delete output buckets (may be unset) |
| `CDR_STORAGE_PATH` | Genomic data root, `gs://vwb-aou-datasets-controlled/v9` |
| `WGS_*`, `MICROARRAY_*`, `HG38_REFERENCE_*` | Paths to specific genomic callsets and references |
| `AOU_CT_MOUNT` | Read-only gcsfuse mount of the CT data bucket |
| `ARTIFACT_REGISTRY_DOCKER_REPO` | Docker mirror for batch jobs (Docker Hub isn't reachable directly) |

In Python or R, scripts started from Bash inherit these variables. Notebook kernels may not; load
them with `readRenviron("~/.aou/env.list")` in R, or parse `~/.aou/env.list` in Python.

## Storage

- `~/workspace/<resource>` are gcsfuse mounts of workspace buckets. They persist. Local disk
  (`~`) is lost when the app is deleted.
- `~/workspace/aou-tutorial-notebooks/` holds the official tutorial notebooks. They're the
  reference for idiomatic code here. Read them (parse the `.ipynb` JSON) before you invent a pattern.
- gcsfuse is slow for random access and heavy writes. Don't run PLINK/GWAS directly on mounted
  genomic files at scale. Copy inputs to local disk or read `gs://` paths, and write large outputs
  to local disk first, then `gcloud storage cp` to the bucket.
- The CT data mount is read-only. Never write into it.

## Tooling on this VM

Python 3.12 (`pandas_gbq`, `google-cloud-bigquery`, `hail` in local mode), R 4.5 (`bigrquery`),
`bq`, `gcloud storage`, `wb`, plink 1.9, plink2, regenie, bcftools, samtools, tabix, bedtools,
dsub, Cromwell (`$CROMWELL_JAR`, `$WOMTOOL_JAR`), and Nextflow 25.10. Hail at scale needs a
Dataproc app: this JupyterLab VM runs Spark locally.

## Skills

Load the matching skill before you work in an area:
`aou-workspace` (wb CLI, buckets, mounts, env), `aou-cdr-bigquery` (OMOP/CDR queries, cohorts,
surveys), `aou-genomics-data` (which callset/file to use and where it lives), `aou-hail`
(Hail init, MT/VDS, GWAS), `aou-batch-jobs` (dsub, Cromwell, Nextflow).

If something here is missing or wrong (variable unset, import fails), run
`~/repos/aou-claude-setup/setup.sh --check`. To re-provision, run `setup.sh` from wherever the
repo is cloned.
